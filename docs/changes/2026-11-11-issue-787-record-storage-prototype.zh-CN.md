# #787：共享记录存储候选

## 问题、依据与现行决定

#805 以 `a18db6a4` 为基线，继续只包含命名视图和已有兼容性能优化。存储改造独立推进。依据维护者在 [PR 中的建议](https://github.com/tianma-if/edgeever/pull/805#issuecomment-6874868531)，本候选改用共享记录表、独立元数据和受控字段索引：每条记录保存单元格 JSON，通过 `workspace_id`、`table_id` 隔离；追加、改单元格不重写整表正文。

Cloudflare 免费档的官方限制、已测规模、空间估算及冻结物理表的同条件历史对照，见[容量与方案对照](2026-11-17-issue-787-storage-comparison.zh-CN.md)。空间外推不是云端稳定支持承诺。

此前独立物理表、真实列和影子列的实现暂停，原工作区和证据完整保留，不在本候选中继续发展。共享 JSON 的早期实验、查询编译器和严格类型转换器可以复用；物理表的性能与兼容证据不能用于证明本候选已通过。本次只在本地使用合成数据，不访问云端 D1、部署或消耗免费额度。

## 允许变更与验收清单

1. 在独立候选中实现使用现有 `DatabaseAdapter` 的共享记录服务；D1 与 Docker/SQLite 共用业务逻辑。不增加依赖、Durable Object、队列或其他存储服务。实验表结构由显式本地实验入口加载，不添加自动迁移或改动 #805 的生产入口。
2. 字段、命名视图、修订号和记录总数保存在小元数据中；记录 JSON、顺序、稳定 ID、附件值及空值保持。使用现有类型、容量及严格转换规则，不新增产品上限、默认重试或静默 fallback。分页只返回当前页；整次分页不得逐页重复全表计数。
3. 原型覆盖追加、记录编辑/删除、元数据修改及乐观并发。写事务同时推进头部、不可变记录历史和搜索投影，失败不留下部分修改。错误工作区不可读取或写入；过期离线基线返回 409，原草稿由调用方保留。旧正文只作为迁移输入/逻辑导出，不作为第二个活动数据源。
4. 受控索引只来自已保存视图，不因临时查询建索引。优先复用共享 JSON 的局部表达式索引及已有查询编译器，索引范围限定工作区与表；记录写入、视图修改、字段类型变化及历史恢复时同步维护。用实际查询计划、完整翻页、多个逻辑表和宽表评估读写与空间，不能把本地指标当作 D1 计费或 Workers CPU。
   沿用原方案已经确认的查询契约：文本按 Unicode 码点顺序、空值最后、同值保留行顺序；客户端离线排序与 SQLite/D1 BINARY 一致。该契约替代旧运行时的 locale 排序，中文、大小写和补充平面字符的顺序可能与旧版不同，须验证在线/离线结果一致。
5. 类型变更使用分批预检/准备和原子发布，复用严格转换器。转换失败阻止发布，表示变化需确认；源修订变化使预检失效。执行期间仅该表暂停写入，读取旧值；取消清除未发布准备。共享方案保留每个修订的字段与记录，验证跨类型历史读取和恢复；原物理表候选不跨类型回放的边界不再作为新方案的限制。
6. 本地验证真实 `a18db6a4` 旧表序列化数据进入共享存储、保留旧/新视图和附件、离线冲突、历史恢复及逻辑备份往返。复用已有归档组件检查可读取范围，不修改 ZIP 格式或旧条目上限。API/存储原型验收与正式客户端接入、原生平台和云端验收分别报告。
   候选快照导出复用原方案的 `nullable-v1` 标记，以区分文本/单选等字段的 null 与空字符串。仅显式候选导出携带该标记；未带标记的旧正文继续按原规则读取，普通序列化入口保持不变。
7. 先写能验证上述新行为的集成测试，再实现。完成后运行定向集成、根类型检查、移动端类型检查和 Web 构建；核对完整 diff 与本清单。提供可复现本地驱动、最新设计、代码位置和有效证据。

## 临时组合排序修复范围与验收

已复现的阻塞是未保存的单选分组加数字次排序：已有数字字段索引未被使用，宽表完整翻页反复扫描/排序，约 376 万条本地 VM 指令。先复用查询编译器的有限分组能力和已存在、方向匹配的次排序索引。单选单字段排序可按原行序分组读取；单选加一个已索引字段可按分组和后续索引键继续读取。不会因为临时查询新增索引、缓存、表结构、外部服务或客户端状态。

允许修改查询计划及其共享 JSON 布局适配，按单选组选项顺序、次排序值和行序生成互不重叠的读取段，每页最多组装 51 个候选。二级重复值使用值相等加行序游标，后续值和空值分别读取，防止在同值段反复扫描。每段只补齐当前页余量；最终记录回读必须同时限定工作区和逻辑表，不能只按 position 关联。

保持字段类型、旧筛选/OR 语义、排序方向、空值最后、稳定行序、50 行页、游标身份/修订校验、首个筛选页计数一次及临时查询不建持久索引的约定。优化仅在现有索引和可分组前缀满足条件时选择；其他合法查询继续原有查询路径，不新增拒绝或产品容量限制。完全没有适用排序索引的任意文本等组合仍需单独评估，不承诺仅靠 SQL 改写消除其所有重复扫描。

先用 500/1,000 行完整翻页的累计 SQLite VM 指令增长回归复现，再实现；翻倍数据时累计工作应接近线性，而非随页数与行数乘积增长。语义验收覆盖空值、大量同值、两个方向、OR、未请求总数、相同行序的其他表、旧游标失效，以及绑定参数。用同一份既有宽表数据库和原始查询记录比较前后成本；结果载荷、精确计数次数与数据库总空间/索引均纳入核对。最坏后果是漏行/重复、空值排序错误或跨表回读，以完整结果对照和游标测试检查；回退只需撤回新查询分支，存储无需迁移。

## 正确性与恢复契约核对

本地候选审查覆盖共享记录写入/读取、查询索引、类型任务、历史与显式快照导入，以及实际本地消费方。原性能与产品接入边界保持，以下修复依据已复现错误和现行解析/事务契约，不新增容量、Unicode 拒绝规则、缓存或重试。

- 记录、字段和表身份必须无损传输；修复原生绑定对已接受 UTF-16 标识的解码/编码损失，避免重复写入和计数损坏。分页游标必须来自完整逻辑排序键，不能使用数据库绑定有损解码后的文本；普通输入在既有截断处形成孤立 surrogate 时仍须完整翻页。复用客户端排序键，覆盖文本和附件，保留所有已支持值。
- 合法字段 ID `__proto__`、`constructor` 和 `toString` 作为普通单元格键保留。解析和记录规范化只读取自身属性，缺失键沿用既有空值规则；构造结果时避免触发对象原型 setter。覆盖共享存储、显式快照导出/重读以及缺失值，不能通过拒绝这些 ID 避开已复现的丢值路径。
- 附件原值为 null 时，新写入归一化仍用数组；查询也按权威 null 识别旧候选的空字符串投影，无需回填，避免旧 contains/eq 对空字符串执行 json_each；逻辑原值不变。SQL 单选选项和其他合法文本含 NUL 时使用无损常量表达式，不能因拼接 SQL 失败或新增拒绝。
- 文本与附件名的 contains 保留现有 JavaScript UTF-16 匹配语义，包括查找补充平面字符的一半。普通查找继续使用 instr；仅首个低 surrogate 或末个高 surrogate 使用按字节对齐的额外匹配。修复参数替换误把表 ID 中的问号当占位符的问题，表身份仍作为数据处理。
  D1 的 LIKE/GLOB 模式最多 50 字节。已由 instr 确认的最长字面锚点不再放进 GLOB，只检查锚点两端的短边界模式；长筛选值继续接受。用本地 SQLite 显式设置同一模式长度限制验证，不能只依赖本机默认限制，也不据此宣称真实 Workers CPU 达标。
  合法的 40 个长字段 ID、40 个选项、8 个筛选及完整排序组合还会超过 D1 的 100 KB SQL 限制。非索引单选排序的选项提取改用等价且更短的 JSON `->>` 表达式，保留现有索引表达式和参数复用；不缩减字段、选项或筛选范围。用同时限制 SQL、绑定参数、函数参数及 GLOB 长度的 SQLite 重放完整翻页，并复核累计查询工作量。
- 初始化在写事务内复核当前可见性，失败无候选数据；成功写入回执使用本次提交修订，不能混入随后其他写入的版本；启动转换在同一事务内复核任务仍为 preflight，已取消任务不能被旧启动请求复活。预检持久化只保留执行所需的问题标识，不把整列原值/目标值复制到单个 JSON 状态字段；调用方诊断仍完整。
- 元数据重排按稳定字段 ID 精确比较，不因 locale 把不同 ID 判为相同；记录 ID 沿用原解析器已有的 80 字符边界，防止写入后逻辑导出不可读。
- 字段标题/顺序变化时，当前搜索投影同步且原子更新；不改记录原值或补写无变化的记录历史。使用行序游标逐批读取一次，视图修改不重算无关投影。
- 显式快照/历史导入整体原子提交：后续输入或数据库步骤失败时，不能暴露首份历史作为完成的当前表，也不能妨碍重试。复用初始化与替换的语句规划，不引入额外持久化任务。
- 删除调用方从不设置的旧物理表查询选项、不可达 SQL 和无实际参数的通用占位符替换层；保留实际使用的普通 keyset、单选索引和分组计划。用原有查询回归与同库对照核查行为及成本，不能以删行数作为正确性依据。

## 保持不变的边界、风险与回退

普通笔记、#805、主工作区及暂停的物理表工作区不修改。当前产品的自动迁移、同步队列、客户端页面、公开表单生产路由及备份默认入口不在本次切换范围；候选服务通过显式本地驱动使用，不把独立原型描述为已发布修复。既有原生平台能力、权限及资源配额不放宽。

主要风险是跨工作区串读、并发覆盖、历史头部与单元格错配、索引在结构修改后陈旧，以及把整表成本移到历史或翻页。以事务、修订门禁、历史快照和累计查询计量验证。回退为停止本地候选并继续使用原基线；本次没有生产数据迁移。云端 CPU/额度、正式客户端接入、全平台旧版升级及正式迁移/回退仍需后续独立验收。

## 完成核对

共享记录候选已覆盖记录追加/编辑/删除、独立字段与视图元数据、按页查询、乐观并发、即时搜索投影、按记录版本历史、分批类型准备/取消/原子发布及跨类型历史恢复。写事务同时校验来源修订、当前可见性和该表的转换门禁；单行编辑只新增一份记录历史。源码入口和复现方法见 [本地驱动说明](../../scripts/experiments/shared-records/README.md)。

当前定向验证为 51 项测试、1,969 个断言通过；根类型检查在 D1 模式长度修复后通过，移动端类型检查和 Web 构建在共享解析器修改后通过，后续仅 API SQL/测试变化复用该结果。HTTP 验证复用已有权限检查，覆盖跨工作区拒绝、离线过期草稿 409 和并发写入。现有 ZIP v2 在关闭源实例后恢复了 8 行表的当前数据、两份跨类型历史、附件单元格引用和 7 字节附件，包含 null 值；附件 fixture 使用有效 byteSize，并显式检查非空引用。这份证据不代表近上限大归档已通过。

合法原型同名字段的文本/附件值及缺失值可经普通解析、共享记录写入和显式快照导出/重读完整保留；特殊字段的类型转换与历史恢复也通过。额外的 28 次连续新增、编辑、删除及恢复操作完成 434 份历史快照与导出对照；日期、复选框、旧版筛选和选项外单选值的 70 组查询、105 页结果与离线逻辑一致。D1 限制修复后重新完成 32 组同库查询成本对照，结果与累计指标保持一致。

已复现的游标损失、UTF-16 筛选差异、空附件投影、可见性竞争、取消后复活、错误提交回执、字段身份/搜索投影、超大预检状态和导入部分提交均有对应回归。最新代码经正确性、简化及既有契约核对，当前审查范围内未留有已确认未修复的实质问题。D1 模式长度修复前的 UTF-16 独立本地标量实验保留为历史证据，不能作为当前实现耗时或云端请求 CPU；当前匹配仍保留 instr 的普通路径，长边界值在显式受限 SQLite 下验证。当前结果和源码指纹见 [审查验收摘要](evidence/2026-11-16-shared-records/review-loop.json)。

2/10/30 张 1,000×10 表及两张 1,950×38 富文本表完成了 32 组完整查询结果比对。宽表全量视图 39 页，适配器累计返回 2,105 行（含元数据与前瞻行）；已保存数字筛选排序返回 1,635 条记录、33 页，累计返回 1,767 行，只计数一次。每页最多携带 51 条记录。上述数字是适配器返回行，不是 D1 扫描或计费读行。

已保存字段索引在实际查询计划中被使用；同尺寸表的完整查询工作没有随其他逻辑表增多而线性放大。共享表维护更多局部索引仍有写入成本：原始候选在 2/10/30 张表的单行修改分别约 538/642/903 条本地 SQLite VM 指令，不能当作当前版本的完整写入成本，也不能换算为 D1 写行或 Workers CPU。对象占用统计包含主键/唯一索引、局部字段索引、全文索引和历史；原旧笔记正文等基线对象不计入候选对象空间。测量在写入前数据库副本上回放，以保证查询与写入的版本一致。原始候选的维度、空间和基线代码指纹见 [原始验收摘要](evidence/2026-11-16-shared-records/summary.json)；前次查询优化结果及当时指纹见 [查询验收基线](evidence/2026-11-16-shared-records/query-optimization.json)，当前版本以审查验收摘要为准。

已修复复现中的临时单选加数字次排序：按少量单选组（当前不超过两个选项）和已有、方向匹配的次排序索引分段读取，候选总量最多 51，再按工作区/表/行序回读记录。相等值加行序、后续值和空值分开寻址；保留选项顺序、同值稳定性和空值最后。500/1,000 行翻倍的累计工作增长回归通过。以同一份只读数据库回放原始与当前 SQL，1,000 行完整查询由约 992,024 降到 141,324 条 VM 指令（85.8%），1,950×38 富文本表由 3,758,012 降到 277,995（92.6%）。当前记录 ID 使用 hex 无损读取，较前次优化略增指令；32 组结果、每页载荷、计数次数、索引和存储结构保持一致。最终只对当前页候选排序，不能将计划中的临时排序统称为整表排序。

仍未达到完整产品发布门槛：完全没有适用排序索引的连续值排序、更多分组及其他未覆盖组合继续原有查询路径，并不因此成为已优化场景。任意无索引排序要消除重复扫描，需要进一步确定索引或查询结果暂存等策略，不能凭本次 SQL 改写作出通用保证。本次没有扩大自动索引范围、增加缓存、容量限制或拒绝规则。生产自动迁移/恢复、全部客户端与公开表单入口、历史保留策略和大归档默认流程尚未切换；原生跨版本和真实云端额度/CPU 仍需单独验收。正式应用入口未加载实验表结构，因此本次不等于线上大表故障已修复。

实际差异与清单双向核对：新增内容均属于上述本地共享候选、相关共享解析器修复及验收驱动；保留原查询/严格转换实现，未引入新依赖、云资源或额外产品限制。确定性文本排序和 nullable-v1 快照标记沿用原方案约定，普通序列化格式及未标记正文的类型/空值规则不变；原型同名字段的解析修复也适用于未标记正文。
