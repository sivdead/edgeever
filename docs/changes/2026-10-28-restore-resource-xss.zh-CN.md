# Issue 701：备份恢复资源的 XSS 防护

[English](2026-10-28-restore-resource-xss.md)

## 问题与目标

[Issue #701](https://github.com/tianma-if/edgeever/issues/701) 指出恢复接口接受 `kind=image` 与 `mimeType=text/html` 的组合，而资源响应相信 `kind` 并允许内联渲染。修复写入时的不一致，同时阻断已有异常资源的读取风险。在独立工作区基于官方 `main` 的 `b8496806` 实施。

影响范围是 Cloudflare 和 Docker 共用的 API 资源恢复及响应头。旧备份若明确把图片标为 HTML 等不相容类型，会被拒绝；合法旧备份必须仍可恢复。保留既有的可空 MIME 契约和未知/二进制回退，未知类型转为下载而非内联渲染。HTML 等普通附件仍可下载。不迁移或删除现有数据。回滚只需回退代码，无需改写资源；回退也会重新引入漏洞。原生平台运行及部署验收与下述本地检查分开。

备份 Schema 明确允许 MIME 为 null，正式版导出器会保留该值，分片恢复原本回退为 `application/octet-stream`。拒绝这个安全回退会使合法旧备份无法恢复，却无助于阻断 XSS；下载边界由读取时的 MIME 校验保证。

图片 MIME 比较忽略大小写及参数，但入库 MIME 及其参数继续保持原值。校验无需改写存储值，剥离参数反而会丢失 SVG `charset` 等编码信息。

## 允许的变更与验收

| 编号 | 行为 | 验收 |
| --- | --- | --- |
| S1 | 旧式恢复与分片恢复的初始化、完成阶段，对标记为 `image` 的资源按既有 PNG/JPEG/GIF/WebP/AVIF/SVG 白名单校验实际生效的 MIME，同时保留原恢复契约接受的空/未指定 MIME 和 `application/octet-stream`。明确不相容的类型返回既有的 `415 unsupported_media_type`。旧式恢复须覆盖元数据 MIME 为 null 时沿用文件 MIME 的路径。图片 MIME 比较忽略大小写及参数，但不改写入库 MIME 元数据或参数；普通附件的 MIME 元数据及大小限制保持原契约。 | 先补充隔离 API 失败用例：显式 HTML/XHTML、元数据为 null 而文件为 HTML、分片恢复及修复前已创建的分片会话。断言拒绝时不新增资源或对象，已有资源不变。验证空/null/二进制图片 MIME 仍可经两条 API 恢复并作为下载输出，正式版导出器生成的备份样例也须包含 null MIME。两条恢复路径均须保留 SVG 编码参数及字节。 |

## 保持不变的边界

- 除 S1/S2 外，不改变备份格式、Schema、Migration、认证、API Token、权限、上传大小、重试或 fallback。
- 不禁止 HTML 附件，不清洗笔记正文，不删除历史资源，不操作他人的实例或数据。
- 通过独立提交和贡献分支交付，并向上游提交关联 #701 的 PR；不自动合并、部署或发版。原 #657 工作区及其未提交改动保持原样。
